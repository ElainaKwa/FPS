## 1. 目标与范围

目标是提高扩展性、降低数据与代码耦合，而不是禁止修改 C++。调整已有数据不应牵动执行逻辑；新增行为允许编写代码，但改动应集中在直接相关的行为实现、参数结构与测试中，避免角色、地图、音频和拾取多处同步修改。

| 变化 | 预期修改范围 |
| --- | --- |
| 修改伤害、弹药、时长、曲线、模型和声音 | 对应定义或资源资产 |
| 使用已有行为新增型号 | 新定义、资源、明确的目录及地图配置；不增加型号专用逻辑分支 |
| 新增实质不同的行为 | 集中的行为模块、参数结构与测试；必要时修改 C++ |

本轮保留现有 AK、M4、MP5、UMP45、M9、Heavy Pistol，新增一把固定三连发步枪。不新增霰弹枪，不实现逐发装填、配件、耐久、穿透、变倍等示例功能。新增步枪的名称、精确数值和资源制作细节尚未在访谈中确定，不能写成用户已指定。

采用有限、可验证的行为扩展点，不建立任意行为拼装、脚本状态机、通用属性包或插件框架。原教学地图保持可用，保留无关资产和用户改动。

## 2. 当前问题与事实校正

下列入口为讨论时核对的代码位置，实施前应重新检查，不依赖可能过时的行号。

| 主题 | 当前问题或边界 | 重构方向 |
| --- | --- | --- |
| 型号身份 | `FPSMatchFlow` 将数字强转型号，`FPSWeapon1..6` 按枚举顺序解释 | 稳定身份、显式地图引用、单独展示顺序 |
| 资源约定 | `FPSWeaponData` 拼接网格路径；角色拼接 `Fire_<Model>`；音频子系统维护另一份列表 | 定义显式引用资源，不要求多处同步命名 |
| 数据编辑 | Catalog 运行时 `NewObject` 创建定义及曲线 | 可保存、可编辑的定义与曲线资产 |
| 校验 | 缺少完整目录、数值及引用校验 | 编辑器、构建检查及运行入口校验 |
| 参数散落 | 分类反推槽位；部分时长、表现参数在代码中 | 分类与槽位独立，行为和表现参数明确归属 |
| 射击语义 | `bAutomatic` 仅两态 | 共用单发、全自动、三连发执行机制 |
| 实例 | 已有 GUID 与弹药，但缺少随枪保留的运行限制 | 明确冷却、后坐力等状态生命周期 |
| 后坐力 | 六把枪共用代码生成的八个键模板，主要只有幅度差异 | 独立可编辑曲线及覆盖范围校验 |
| 调度 | 现有组件复制状态机调度动作 | GAS GameplayAbility 为核心，集中冲突和中断规则 |

注意以下表述已经校正，不应继续作为错误前提：

- 当前 Catalog 是 `TMap`，不是已证实的枚举数组下标；实际已确认的耦合是整数转换、地图标记顺序和资源名称拼接。
- `PresentationScale` 并非不生效，拾取模型使用 `PresentationScale * .65f`；问题是隐藏的展示倍率及职责混杂。
- 新模式人机经 `FireAuthority()` 使用定义射速限制，旧教学路径的 `0.27f` 不是新模式人机的固定射速。AI 点射节奏与武器允许的射速是两层概念。
- GUID 已能区分同型号实例。没有皮肤、耐久等字段属于未实现的扩展语义，不代表实例完全无法区分。
- 共享 `State.Weapon.*` 标签名称不等于角色共享状态；每个 ASC 有自己的状态。需要解决的是多个行为来源的标签所有权和计数清理。
- 结构体扩展不自动等于每次全字段重传；应根据真实复制实现与测量判断成本，同时主动拆分接收范围。

## 3. 身份、编辑与加载契约（Q1–Q7、Q21–Q23）

### 身份

- 每种枪有显式稳定 `WeaponId`，如 `Weapon.M4`，组成 `FPrimaryAssetId`，示例为 `WeaponDefinition:Weapon.M4`。
- 不能直接依赖默认资产名作为长期身份。资产改名、移动、显示名修改和展示重排不改变型号身份；修改已使用 ID 必须迁移。
- 每把实际武器继续使用 `InstanceId` GUID。丢弃、拾取保持同一 GUID；同型号不同实例各自保存状态。
- 地图武器台显式引用定义，不再通过 `1..6` 的隐含顺序决定枪械。展示顺序单独配置。
- 分类和装备槽位独立配置；不根据 Rifle/SMG/Pistol 自动推导槽位。本轮仍保留主、副武器两个槽，不扩展背包。

### 编辑来源与校验

- 已保存的 `UPrimaryDataAsset` 和曲线资产是唯一编辑来源；自动导出的只读文本清单用于版本审查，不允许资产与 JSON 双向独立修改。
- 一个武器定义资产内部按职责分组，显式引用网格、声音、曲线。不要为每个小配置都拆独立资产，也不塞入尚未消费的占位字段。
- 重复 ID、非法容量/时长/数值、必需资源缺失明确报错；编辑器验证和项目构建检查失败，运行时本局必需定义无效则阻止进入对局并显示原因。
- 不生成半有效武器，不静默替换为 M4。允许缺省的配置必须明确声明，例如无后坐力要显式表达，不能用漏填曲线表达。
- 接入 Asset Manager 的身份、发现及打包流程；具体扫描配置、加载时机、资产 bundle 和校验命令属于实施设计，不是访谈已规定的 API 方案。

### 兼容范围

迁移并保住现有地图与资产的枪械对应关系。客户端与服务器要求同一内容版本，不支持局中热更新、旧客户端兼容；不为尚不存在的持久武器存档建设兼容框架。稳定 ID 的替换/删除必须有明确迁移步骤。内容版本一致性的具体检查机制尚未规定。

## 4. 定义与实例的数据职责（Q6、Q8–Q15、Q20）

下表描述语义归属，不要求照抄全部字段名或类名。字段类型与组织由实施时结合 Unreal/GAS 设计。

| 分组 | 已确定内容 |
| --- | --- |
| 身份和分类 | 稳定型号 ID、显示名、独立类别与装备槽位 |
| 射击 | 单发/全自动/三连发模式、发间隔、连发数量、连发结束后的冷却、基础伤害、射程 |
| 弹药 | 弹匣容量、初始装填量、初始备弹；备弹属于每把枪，不是角色共享弹药池 |
| 操作 | 换弹时长、检视时长、开镜过渡时长、`EquipReadyTime`、`EquipBlendTime` |
| 后坐力 | 独立曲线、开镜后坐力倍率、恢复等待时间；曲线值为每发增量 |
| 表现 | 第一人称、第三人称、拾取模型及各自变换；可以引用同一个网格；显式枪口/瞄准位置、开火与操作音效、每枪瞄准参数 |

后坐力序号在停止射击达到恢复等待时间后重置，不因松开扳机或切枪立即清零。曲线至少覆盖满弹匣，超过末端保持末值，并校验覆盖范围。保留程序动画并使用对应操作时长驱动；本轮不添加不能实际播放的动画引用、倍镜和准星占位字段。

实例保存 GUID、型号、弹匣和备弹，并保留服务器维护的射击冷却、后坐力序号及最后射击时间等运行状态。时间在切走或落地期间正常流逝，不能借切枪或丢弃再拾取绕过限制。未完成的连发、换弹、检视在丢弃时中断，拾取者仍完成自己的举枪准备。

## 5. 最终操作语义（Q4、Q9–Q19）

### 射击

- 三连发：每次按下触发一轮；松开后完成本轮，弹药不足则打完剩余弹药。必须松开再按才触发下一轮；冷却期间按下不排队。
- 死亡、切枪、换弹中断未完成的连发，不补发被中断的子弹。
- 全自动按住持续射击；单发与三连发不能借提前输入在举枪或换弹结束时补发。

### 切枪

- 立即切到另一把有效武器：当前武器、弹药显示、模型切换立即生效，不等待旧枪收起。
- 新枪经过 `EquipReadyTime` 才能开火，`EquipBlendTime` 独立控制视觉过渡，动画未完全结束不必继续锁住射击。准备时间允许为零。
- **所有当前操作可被有效切枪中断。** 选择空槽不属于有效切枪；重复选择当前武器不重新举枪，也不作为取消限制的途径。
- 新切入的枪重新计算举枪准备，但自己的射击冷却和后坐力恢复状态不能被重置。
- 丢枪后切入另一把枪只执行新枪举枪，不等待旧枪收起。
- 全自动若扳机持续按住，可在举枪准备结束且服务器其他条件满足时射击；单发与三连发需重新按下。

### 弹匣换弹与检视

| 当前动作 | 开火 | 有效切枪/丢弃/成功拾取替换 | 开镜 |
| --- | --- | --- | --- |
| 弹匣换弹 | 禁止开火，不打断换弹、不缓存点击 | 中断换弹 | 允许进入或退出 |
| 检视 | 中断并尝试开火 | 中断检视 | 中断并开镜 |
| 举枪准备 | 准备结束前不能开火 | 中断并开始新的切换 | 准备结束前不接受 |

换弹完成时服务器一次性转移弹药，中断不增加弹药。全自动换弹结束时若扳机仍按住则恢复射击；单发、三连发必须重新按下。换弹期间点击后已松开的输入不补发。

### 开镜与换弹偏好

- 开镜状态与换弹/举枪等动作分别建模，支持换弹与瞄准同时存在；两者独立计时，表现层支持叠加。
- 默认：开始换弹不强制退出开镜，过程中可自由开/关镜，结束保持当前瞄准状态。
- 预留可验证行为选项“开始换弹时退出开镜”：只退出一次，不是整个换弹期间禁止开镜。退出后要松开右键再按才能重新开镜；服务器获知并执行选项。
- **切枪后不自动开镜。** 一直按住右键也必须松开再按。不要实施先前建议过的“保存开镜意图并在新枪准备后自动开镜”。
- 死亡或打开菜单清除开镜意图，避免恢复后意外开镜。设置菜单本身不在本轮交付范围。

## 6. GAS 与网络职责（Q20、Q24–Q28）

- 武器行为明确以 GameplayAbility 为核心，接管开火、换弹、切枪、检视、开镜等动作调度；不保留新 Demo 两套同时运行的调度。
- Ability 按行为复用，读取武器定义参数；普通新增型号不增加专属 Ability，实质不同的行为才增加实现。
- 数据定义、实例状态独立于 Ability 生命周期。取消、重新激活或重新授予 Ability 不能清掉应随枪保留的状态。
- 玩家增强输入与人机决策都发起同一套 Ability 操作；人机只决定何时请求，不绕过 Ability 扣弹或造成伤害。
- 本地预测可预测的操作表现，服务器最终决定弹药、命中、伤害、拾取和状态；拒绝或中断时取消/修正本地预测。具体预测键、Ability 实例化和授予方式由实施设计。
- GAS 继续承担属性和伤害；动作冲突、中断和状态标签统一维护，避免不同来源互相覆盖或取消后残留。

| 接收方 | 数据范围 |
| --- | --- |
| 服务器 | 完整实例状态、弹药、冷却、后坐力恢复及权威动作结果 |
| 拥有者 | 自己的武器、弹药、操作反馈和预测纠正所需状态 |
| 旁观者/其他玩家 | 当前武器身份、可见动作、表现所需时间；不广播无关精确备弹 |
| 地面武器观察者 | 拾取展示需要的型号和弹药；服务器另保留实例冷却等状态 |

保存归属不等于复制范围。实际带宽优化应有观察依据，不宣称采用结构体就必然全量重传。

## 7. 人机难度（Q27、Q31–Q34）

| 难度 | 人机攻击玩家的伤害倍率 |
| --- | ---: |
| 简单 | 0.5 |
| 普通（默认） | 0.65 |
| 困难 | 0.85 |

倍率放在独立难度配置，不写入武器定义或实例。服务器在正常 GAS 伤害流程中，根据攻击者与目标身份应用规则；人机互相攻击、玩家攻击使用正常武器伤害，玩家拾取人机武器后没有隐藏倍率残留。

单机大厅选择难度，开局后整局固定；不支持局中修改，靶场与当前纯玩家联机不受影响。本轮只改伤害倍率。用户最终希望难度也改变人机攻击行为，自适应和情境修正亦值得考虑，均记录为未来事项。
