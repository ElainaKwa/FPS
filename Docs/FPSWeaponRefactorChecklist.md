## 第二阶段：Ability、实例与网络迁移

- [x] 形成有限职责拆分：定义解析、实例状态、Ability 调度、射击执行、表现，避免一个巨大 Ability 或一枪一套重复 Ability。
- [x] Ability 接管开火、弹匣换弹、切枪、检视、开镜及相关取消；所有新增模式操作都经过统一权威校验。
- [x] 玩家增强输入和 AI 共用 Ability 入口，移除人机直接绕过动作流程的执行路径。
- [x] 分离瞄准与换弹等动作状态，实现并验证同时换弹和开镜。
- [x] 切枪立即生效，分离 EquipReadyTime / EquipBlendTime；准备结束前禁止开火与开镜，有效切枪可中断当前动作。
- [x] 重复选择当前武器不触发举枪，不清冷却；空槽请求不作为取消操作。

## 验收矩阵

以下应按真实风险落到有观察结果的测试，不要求每格各写一个机械单元测试。

| 场景 | 必须观察的结果 |
| --- | --- |
| 调整定义数据 | 不需改执行逻辑；各使用端取同一来源，数据清单可审查 |
| 重排/重命名/移动资产 | 原武器台与实例仍对应原枪；稳定 ID 不变 |
| 无效定义 | 编辑器/构建明确失败；运行时阻止相关对局，不静默替换 |
| 客户端三连发 | 服务器正确扣弹和命中；松开继续，切枪/死亡/换弹取消，无补发 |
| 快速切枪、同槽重复、空槽请求 | 不能刷新射击冷却或绕过准备期，状态不滞留 |
| 丢弃/拾取/双人抢拾取 | GUID 和弹药延续；冷却与后坐力恢复延续；不重复认领 |
| 换弹途中开/关镜 | 两状态共存；完成、中断时弹药和镜头一致 |
| 换弹退出开镜偏好 | 只退出一次；需松开再按，换弹中仍可主动开镜 |
| 按住右键切枪 | 新枪不自动开镜；释放再按后才激活 |
| 换弹与举枪后的扳机 | 全自动保持按下可恢复；单发/三连发不缓存点击 |
| 后坐力 | 每枪独立曲线；快速点按/切枪/丢拾不直接清零；恢复时间有效 |
| 网络延迟/拒绝/中断 | 预测可纠正，弹药不重复变化，Tag/表现无残留；参数和实际结果有记录 |
| 玩家与 AI | 共用行为限制，AI 不绕过能力执行；节奏决策和武器射速分离 |
| 难度三个档位 | 倍率分别为 0.5/0.65/0.85，仅人机对玩家生效；拾取后无残留 |
| 基础回归 | GAS 生命/得分、友伤拒绝、重生、结算、原教学地图保持正常 |
| 可见表现 | 模型、枪口、音效、换弹/检视/开镜和 HUD 与动作一致，不以编译替代验收 |
