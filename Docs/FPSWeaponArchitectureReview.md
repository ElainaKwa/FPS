# FPS 武器架构评审（纠正版）

更新：2026-09-30。范围：新 FPS Demo 武器架构。依据为当前工作区代码、UE 5.8 本地源码、实施文档与已有日志。

**本次是静态复核，未编译、未启动编辑器、未重新运行测试。** 下列建议尚未实施；优先级是评审建议，不代表新增玩法自动获得授权。

设计依据仍是 [重构决策](FPSWeaponRefactorDecisions.md)。实施证据见 [第一阶段](FPSWeaponRefactorStage1.md)、[第二阶段](FPSWeaponRefactorStage2.md)、[第三阶段](FPSWeaponRefactorStage3.md)。原版见 [历史归档](Archive/FPSWeaponArchitectureReview.2026-09-29.md)，全目录见 [文档索引](README.md)。

## 1. 结论与已完成基础

当前架构已解决具体型号枚举、运行时生成定义、按型号拼接资源等主要耦合，不需要整体推倒重写。下一步重点是状态所有权、内容契约及表现通知。

- 稳定 WeaponId / PrimaryAssetId 标识型号，GUID 标识实例，武器台显式引用定义。
- 保存的定义和曲线是运行来源，网格与声音显式引用；BR-3 没有向角色、音频或调度加入型号分支。
- GameplayAbility 接管动作生命周期；拥有者与旁观者复制状态已拆开。
- 服务器决定弹药、命中及伤害，客户端已有预测和纠正；这不表示所有网络边界均已验收。
- 分层已有基础，但 Ability 和组件仍共同改写私有状态，角色仍承担较多结算、表现及新旧模式适配。

## 2. 需要修改的重点

### R1（高）：明确 Ability 与组件的状态所有权

**事实：** `FPSWeaponComponent.h` 向多个 Ability 开放 friend，保存具体 Fire/Aim/Timed Ability 指针；Ability 直接修改 Loadout、OwnerState、PredictedShots 和预测键。组件 FinishAction 又读取具体 Ability 的 Command、Instance。

**影响：** 库存、预测纠正和动作生命周期跨类共同维护，修改行为需要了解另一侧内部结构。这是运行时职责耦合，不是编译失败的证明。

**建议：** Ability 管理生命周期，组件提供经过校验的开始、提交、完成、取消接口，携带实例 GUID 和动作标识以拒绝过时回调。复制快照与预测覆盖层明确归属。取消可通过 ASC 句柄/标签或适当事件协作，不必强制全部改成委托。

**验收：** Ability 不任意写库存/快照，旧动作不能给新实例提交弹药，早期预测拒绝不破坏后来操作。把 friend 换成无校验 public setter 不算完成。

### R2（高）：分开输入命令、内部动作与射击周期

**事实：** UFPSEquipAbility 借用 AimOff 命令；CanStart(AimOff) 实际服务“转移后的装备准备”。FireAbility::Step 同时处理模式、计时、连发、跨换弹/切枪重绑和预测，并在不能射击时每 0.02 秒重试。

**建议：** 内部 Equip 使用独立语义；扳机意图、当前实例的一轮射击、等待武器就绪分别表达。可由冷却截止时间、换弹/举枪结束通知唤醒的地方，减少轮询。

**验收：** 全自动保持输入可恢复，单发/三连发不补发，切枪后不自动开镜；空仓、跨模式切换和长期按住有明确行为。轮询成本尚未测量，不直接判定已发生性能问题。

### R3（高）：补充两端内容一致性检查

**事实：** 当前复制 WeaponId，但没有校验两端定义内容一致性。

**影响：** 服务器仍决定最终伤害，但客户端可能使用不同容量、射速、准备时间或曲线进行预测和表现，造成误导与反复纠正；不是客户端独立决定最终伤害。

**建议：** 定义本局依赖集与稳定内容清单，开局前核对版本/摘要，不一致明确拒绝。规定摘要字段、资源版本及格式版本；避免把不影响身份的目录移动误当成型号变化。

**验收：** 同 ID 一端改容量/射速后不能静默连接；相同内容正常连接。范围不扩大到旧客户端兼容或局中热更新。

### R4（高）：按本局依赖进行运行准入与加载

**事实：** Catalog::Discover 全量扫描 Asset Registry 并 GetAsset；Initialize 同步验证全部定义，任意错误使目录不发布。CanAct 检查全局 ValidationError。定义的 TObjectPtr 硬引用会连带加载资源。

**影响：** 与“本局必需定义无效才阻止”不一致，无关模式也承担初始化。随数量增长的实际成本未测量。

**建议：** 分离全项目编辑器/发布校验与本局运行准入。让 Asset Manager 管理发现、依赖集及加载生命周期，结合软引用/资源分组决定战斗数据与各视角资源的加载时机。只换查询 API 不改引用和生命周期，不算按需加载。

**验收：** 必需定义错误阻止本局，不相关错误不阻止无关局，但全项目发布校验仍失败。开局前资源就绪，加载耗时和驻留有观察记录。

### R5（中）：明确单次射击上下文和伤害属性语义

**事实：** Changed 将 Definition()->Damage 写入 ASC WeaponDamage；角色结算读取该属性，乘难度倍率后写入 GameplayEffect SetByCaller。

**影响：** 通过共享可变属性传参，依赖每次变化正确刷新。未来增益加入时，基础值、缓存值与可修改属性的含义易混淆；目前没有据此复现伤害错误。

**建议：** 服务器提交射击时捕获必要的型号/实例、基础伤害和上下文。定义提供基础值，GAS 负责明确的修正及生命变化。若保留可修正 WeaponDamage，规定更新和快照规则；若只是展示缓存，则不作为权威结算的隐式中转。无需机械限定为两个 float 参数。

**验收：** 切枪与预测纠正不导致串用伤害，保留难度倍率、友伤和结算过滤；不绕开 GAS 直接扣血。

### R6（中）：明确动作结果，避免弹药变化推断音效

**事实：** RefreshPresentation 用同 GUID 弹匣增加推断 ReloadEndSound，操作音效仅本地玩家播放。远端已有复制动作和截止时间，AvatarVisuals::UpdatePose 已驱动第三人称换弹手臂。

**建议：** 用带实例与动作标识的提交/取消结果驱动表现并去重；持续状态仍用于还原进行中动作，避免后来进入相关范围的旁观者无法恢复姿势。按需要补远端音效、检视和举枪表现。

**验收：** 预测回滚不误播完成，确认不与本地预测双播，旁观姿势与动作一致。不能描述为“远端完全没有换弹表现”。

### R7（中）：整理表现参数和时间语义

**事实：** 非 ADS FOV 为 92；枪体插值速度采用 5.6 / EquipBlendTime，FOV 采用 2.8 / AimTransitionTime，多个姿势目标共用位置插值。

**建议：** 基础 FOV 归玩家/相机设置；明确字段是完成时长还是插值速度；分开装备、ADS 和后坐力回弹的过渡，零时长显式直达目标。

**验收：** 正值行为符合声明，零值立即完成，调整举枪时长不影响所有枪体动作。相关 UE InterpTo 在速度不大于零时直接返回目标，原评审“零速卡死”不成立。

## 3. 后续结构整理

- 角色/规则：逐步收敛命中、表现和新旧模式判断，可以提取接口/适配，保留教学行为；不强制一轮把角色变成纯装配壳。
- 模式表达：集中 bStructuredMatch、bTraining、字符串模式背后的策略，不只是把字符串改枚举。
- AI/地图：巡逻点、交战距离、寻弹参数移向地图/AI 配置，为新地图降低修改成本；不自动扩展战术玩法。
- 测试接缝：随接口改造减少 smoke 直接写私有状态，保留有效回归；white-box 测试不是天然错误。
- 查询成本：拾取物遍历、每个资产校验反复扫描目录值得测量，不能无数据地要求全部建注册表或缓存。

## 5. 建议执行顺序与待办

以下是评审后续建议，未实施，也不覆盖已确认的玩法规则。

- [ ] R1：状态所有权及有校验接口；测试过时完成、取消和预测拒绝。
- [ ] R2：内部 Equip 语义、扳机意图与发射周期分离，减少可替换轮询。
- [ ] R5：权威射击上下文和 GAS 属性语义。
- [ ] R3 + R4：共同设计本局依赖集、版本/内容一致性、分级校验和加载生命周期。
- [ ] R6 + R7：表现结果、去重及过渡语义，补旁观验证。
- [ ] 后坐力命中同步专项测试及复制/加载测量，记录条件和结果。
- [ ] 在上述边界稳定后按收益推进第 3 节整理。

网络/GAS 修改必须检查真实服务器和客户端；减少 friend、换容器或编译成功不等于验收。沿用已有测试并增加针对性用例，不无条件扩大未承诺玩法。
