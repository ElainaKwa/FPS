## 2. 共同视觉方向

核心是**克制的工业行动终端与配套工业战斗环境**：结构清晰、硬表面为主、材质有区分、标识有功能、细节服务辨识。以 [修订后的样稿](../UI/MockupReview.md) 作为跨 UI 与三维资产的视觉起点。

| 维度 | 整套统一要求 |
| --- | --- |
| 形体 | 清晰的大轮廓与功能分件，直线、平面和少量切角；适度倒角帮助识别体积，不到处增加碎片结构 |
| 颜色 | 黑白灰及低饱和材质本色构成主体，工业黄只承担有限的引导/标识；红蓝服务阵营，危险提示另有语义 |
| 材质 | 混凝土、涂装金属、裸露金属、聚合物、织物等有合理区分；粗糙度与局部磨损辅助读形，避免满屏脏污或镜面反射 |
| 图形 | 功能编号、区域标识、方向箭头与少量警示条纹，与 UI 的工业语言协调；先保证标识含义和可读性 |
| 细节 | 从游戏镜头和交战距离决定细节密度，第一人称近景有必要细节，远景靠轮廓和材质分块辨识 |
| 光照 | 角色、武器、掩体与背景分离，强光/暗处仍能读懂状态；重点物件不靠全身发光表达 |

用户在 UI 中选择轻量剪影，直接约束的是图标和界面武器展示，不等于要求所有三维模型都保持原程序模型的低面数，也不等于承诺样稿中所有高细节几何。具体面数、贴图尺寸、材质数量、LOD 与渲染方案须结合游戏内效果和性能确定。

样稿中的材质、工业空间、持枪观感可用于美术方向；其具体楼层、路线、武器配件、远景和角色不能自动成为必须逐件复刻的资产清单。

## 3. 标识与命名

- “MCP”及“MCP / FPS”是测试代号，不作为对玩家展示的游戏名称、组织名、Logo、墙面涂装、枪身刻字、角色徽章或菜单页脚。
- 主菜单不常驻“PC · 键鼠”等平台/输入方式说明；具体操作仍按需展示 `P`、`Esc`、`R` 等真实按键。
- 正式名称尚未确定，不擅自补一个品牌。当前用“行动终端”“本局配装”等功能标题及必要区域标记即可。
- 本条约束对玩家展示的美术与文案，不要求重命名 `MCP_Test` 工程、C++ 模块、代码路径或 Unreal 资源根目录。历史原始提示词与初稿作为来源证据保留，不再作为当前制作模板。

## 4. 地图与场景建模

制作覆盖现有竞技场 `LV_FPSFoundry` 和靶场 `LV_FPSTraining` 的成套环境语言，包括地面/墙体、结构模块、掩体、出入口、基地、训练设施及必要标牌。

- 用统一尺度、材质和模块化硬表面结构建立工业设施感；大面积灰色基底，少量黄黑功能标识和阵营区域提示。
- 中央交战区、侧路、基地入口和靶场射击线能从轮廓、分区和导向标识辨认；装饰不冒充可通行入口或可用掩体。
- 从主要玩家视角检查角色与背景的明暗分离，避免密集纹理淹没目标、枪械拾取物或准星。
- 本轮风格确认不改变地图尺寸、路径、出生安全区、遮挡、导航或楼层。尤其样稿的高架平台不直接转成新可行走区域；现有 AI/碰撞/玩法是否支持必须另行验证。
- 模型升级后保留或重新验证基地边界、出生点、武器台、碰撞与导航标记，不能只看静态画面。

2026-10-13 用户要求新增参考沙二路线关系的更大型对战地图，并明确风格与产物遵守本规范。该新增地图采用工业设施、灰色混凝土、金属、少量工业黄导向及红蓝基地标识；参考关系只用于布局，不沿用沙色城镇或拱门装饰。该要求允许新增地图扩大规模和路径，不改变以上对既有地图美术替换的边界。新增源文件、导出、预览及 Unreal 资产按资产组织规范交付，实际接入和验收见 [工业关隘地图记录](../Maps/IndustrialCrossing.md)。

## 5. 枪械系列建模

为当前启用的枪械建立同一系列的造型与材质质量。型号清单和参数以现有武器内容及定义为准，样稿显示的几把枪不是全部制作范围，也不增添未定义的新武器。

- 保留各型号的主要轮廓和类别差异，统一材质表现、边缘处理和细节密度；不同型号不强行做成完全相同的外形。
- 第一人称、第三人称、地面拾取和 UI 剪影必须能对应到同一型号。UI 继续采用统一朝向的单色剪影/线稿，从确认后的项目模型提炼，不以生成图中的任意枪型充当权威外形。
- 枪口、瞄具、握持区、弹匣和运动分件围绕现有使用需求设计；更换模型后复核握持、ADS 对齐、遮屏面积、换弹表现与碰撞。
- 枪械表面不加入测试代号；少量功能性刻线和材质分块用于读形。样稿中的瞄具/配件不意味着新增改装系统或改变现有配件配置。
- 外观升级不改变伤害、射速、弹药、服务器状态和拾取/丢弃规则。为表现需要增加的分件或动画另有实施记录。

## 6. 人物与第一人称资源

制作范围包含第三人称人物、第一人称手臂/手套以及与枪械和环境协调的防护装备。外观采用工业防护与战术功能相结合的方向，统一硬质护片、织物/柔性关节与必要的阵营识别。

- 先保证头、躯干、四肢和持枪姿态的清楚轮廓，近景与远景细节分配不同；敌我辨识不能只靠很小的色块。
- 第一人称手臂、手套与第三人称人物属于同一套设计；检查握持、换弹、开镜、切枪与移动时的遮挡和穿插。
- 不通过大型肩甲、装饰挂件或特效误导受击范围、遮挡瞄准或破坏动作可读性。
- 当前项目为装甲训练机器人和程序关节表现，这是现状而非已确认的最终角色外形。最终人物比例、头盔/面部方案、机器人或其他表现细化、骨骼和动画路线仍需具体角色样稿与制作验证；当前只锁定共同风格和完整人物资源的制作目标。
- 不从“人物建模”自动扩展出新职业、角色技能、商城皮肤或额外 NPC 系列。

## 7. 制作衔接与验收

建议按“统一材质/尺度与标识 → 代表性场景区块、单把枪和人物外形验证 → 扩展到整套资产 → 游戏内联调”的顺序推进，顺序是实施建议，不是已经完成的里程碑。

| 工作线 | 已确认的目标 | 当前证据与状态 |
| --- | --- | --- |
| UI | 延续工业终端布局与轻量剪影，去除代号和平台页脚 | 菜单、HUD、配装基础界面已实现；见接入记录 |
| 地图 | 竞技场和靶场形成统一工业环境 | 十二模块已保存；双地图应用材质及外观层，运行检查见接入记录 |
| 枪械 | 当前启用型号的模型、材质和 UI 外形统一 | 七枪模型和剪影已绑定；实机持枪检查见接入记录 |
| 人物 | 第三人称人物与第一人称手臂/手套成套 | 机器人基型及15个派生部件已接入程序关节；精细人物按用户要求暂缓 |

制作时需要提供可编辑源资产和可定位的导入/更新记录，并维护对当前资源的引用。不得用本次文档状态替代实际交付状态。涉及二进制 Unreal 资产应通过适用的编辑器流程处理，保留无关地图及用户修改。

视觉验收至少覆盖 UI 与场景同屏的一致性、战斗距离下敌我识别、各枪型辨识、明暗场景、第一/第三人称动作与遮挡。资产接入还要检查碰撞、出生和基地规则、AI 可达性、Cook 与性能；若影响网络或 GAS 行为，按相关文档进行服务器和客户端实际验证。基础游戏接入与当前验收见 [接入记录](Integration.md)，首批资源制作仍见 [制作记录](AssetProduction.md)。
