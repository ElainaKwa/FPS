# FPS 移动重构与体力系统设计决策

- 用途：设计决策
- 适用范围：新 FPS Demo 玩家移动、体力、武器衔接与相关 HUD；对战和靶场
- 状态：移动讨论 Q1–Q26 已确认；实施与验收进度见独立记录
- 最后更新：2026-10-13

本轮重做普通移动、疾跑、蹲伏和跳跃的操控手感，增加体力系统，让持续赶路与连续战斗机动产生取舍。普通移动保持利落，疾跑有适量加速与刹停；体力耗尽不削弱普通移动、瞄准或射击。

本文是本轮移动重构的行为依据。后续回答覆盖早期建议：疾跑最终消耗为 **6/秒**；松开所有方向键**保留疾跑意图**；20 点启动门槛只检查**新的一次疾跑**。下列数值是已确认的首轮试玩基线，可依据实际体验调参，不代表最终平衡值。

本轮实际改动、版本、运行证据及未验证边界见 [移动实施与验证](MovementImplementation.md)；本文的验收表是要求，不是通过结果。

既有 [角色与模式规则](DesignDecisions.md)、[枪械规则](../../FPSWeaponRefactorDecisions.md) 和 [UI 设计](../UI/DesignDecisions.md) 在未被本轮明确修改的范围内继续有效。[早期移动操作说明](../../FPSWeapons.md) 可作历史背景，不能覆盖本文的新规则。此前 [角色扩展验收](ExtendedAcceptance.md) 不证明本轮移动或体力系统已经实现。

## 目标与适用范围

- 首版包含行走、疾跑、蹲伏、跳跃、体力、必要武器衔接、输入设置及 HUD 反馈。
- 不扩展滑铲、翻越、趴下、攀爬、蹬墙、闪避或地图重制；本轮不增加疲劳引起的瞄准漂移、武器数值惩罚或强制镜头模糊。
- 单机对战、联机对战和靶场中的玩家统一启用新规则，靶场保留真实移动与体力限制。
- AI 暂不消耗体力，不因体力触发弱跳或蹲伏惩罚；继续现有移动决策，不新增跳跃寻路、蹲伏战术或复杂体力决策。生命、阶段、武器、阵营与基地边界等原有限制仍有效。
- 原 `LV_NetSyncFPS` 教学地图保持原操作及行为；独立 `LV_NetworkBasics` 不在本轮范围。
- 保留无关地图、资产和已有改动。地图中正常跳、弱跳的实际越障能力需要验证，不能为了让测试通过而自动改地图。

## 首轮试玩参数

| 参数 | 已确认初值 | 说明 |
| --- | --- | --- |
| 普通移动速度 | 480 cm/s | 普通移动快速起停与反向 |
| 疾跑速度 | 720 cm/s | 基础速度的 1.5 倍 |
| 蹲伏移动速度 | 240 cm/s | 基础速度的 0.5 倍 |
| 站立 ADS 移动速度 | 312 cm/s | 基础速度的 0.65 倍 |
| 疾跑提速目标 | 约 0.25 秒 | 从普通移动进入疾跑的手感目标 |
| 退出疾跑减速目标 | 约 0.15 秒 | 回到普通移动速度；不延迟状态中断 |
| 正常起跳速度 | `JumpZVelocity = 500` | 降低原先的 650；固定力度，不通过长按增高 |
| 弱跳上升高度 | 正常跳跃的 50% | 是高度比例，不是起跳速度直接减半 |
| 落地后再次起跳间隔 | 0.2 秒 | 正常跳和弱跳均适用 |
| 最大体力与出生体力 | 100 | 每次新生命回满 |
| 实际地面疾跑消耗 | 6 点/秒 | 满体力连续疾跑约 16.7 秒 |
| 正常跳跃消耗 | 20 点/次 | 成功起跳扣除一次 |
| 进入蹲伏消耗 | 10 点/次 | 成功从站立进入蹲伏扣除一次 |
| 新的一次疾跑启动门槛 | 20 点 | 达到门槛后可以持续到零；不是额外启动费用 |
| 恢复延迟 | 1.5 秒 | 停止消耗后计时 |
| 恢复速度 | 25 点/秒 | 无新消耗时，从耗尽到满约 5.5 秒，含延迟 |
| 正常蹲伏再次进入间隔 | 0.35 秒 | 本次进入能扣足 10 点时适用 |
| 低体力蹲伏再次进入间隔 | 0.8 秒 | 本次进入不足 10 点时适用，包含零体力 |
| 疾跑转射击准备时间 | 0.15 秒 | 首版统一配置；不替代武器原有就绪限制 |

蹲伏与 ADS 同时存在时使用蹲伏速度，不继续叠乘减速。加减速时间是手感目标，实际轨迹受起始速度、碰撞等影响，不应以强行插值位置绕过移动模拟。空中保留起跳动量的规则独立于地面退出疾跑的减速目标。

## 疾跑意图与实际移动

必须区分玩家保留的疾跑意图与角色是否正在实际疾跑。只有向前或斜前方的实际地面疾跑移动持续消耗体力。仅按 Shift、静止、顶墙而没有实际移动或处于空中，不持续扣疾跑体力。

| 情况 | 意图与行为 |
| --- | --- |
| 新触发疾跑 | 至少 20 点体力且满足移动、姿态和武器条件才可启动 |
| 从静止按疾跑并向前 | 允许启动，实际移动后才开始持续消耗 |
| 松开所有方向键 | 保留意图，停步不耗体；再次向前可继续同一次疾跑 |
| 向前输入但被墙挡住 | 保留意图；没有实际移动时不耗体 |
| 后退或纯侧移 | 立即清除意图；需要重新触发才能疾跑 |
| 蹲伏、开火、ADS、换弹、切枪、检视 | 结束疾跑并清除意图；动作结束不自动恢复 |
| 体力耗尽 | 清除意图；恢复到至少 20 点后仍需重新触发 |
| 跳跃离地 | 保留意图与起跳时的水平动量，停止地面疾跑持续消耗 |
| 落地 | 意图仍有效且方向、体力和武器条件允许时继续 |
| 菜单、死亡、回合结束 | 清除意图，不自动恢复 |

Q26 的最终规则是：**启动门槛只适用于新的一次疾跑**。例如剩 12 点时停步，意图仍有效且没有发生其他中断，再次向前可以继续消耗到零，不重新要求 20 点。耗尽、后退等已清除意图的情况不属于这个例外。

后退输入立即结束疾跑状态和耗体，但已有速度可按短暂减速过渡；空中后退清除意图，不瞬间抹掉已有水平速度。按住模式的“重新触发”是松开再按；切换模式是再次按下。

## 跳跃与空中控制

- 体力足够时正常跳并扣 20 点；不足时采用固定高度的弱跳并扣完剩余体力。零体力仍能弱跳，不按剩余体力连续改变跳跃高度。
- Space 每次按下最多触发一次；按住不在落地后自动连跳，也不延长上升或增加高度。
- 疾跑起跳保留当时水平动量，空中只能适量修正方向，不能像地面一样立即反向。弱跳同样保留对应水平动量，主要降低垂直上升高度。
- 连续正常跳或弱跳不能积累额外水平速度。落地后的 0.2 秒再起跳间隔两者共用。
- 蹲伏中按跳跃，有足够站立空间时自动站起并跳跃；空间不足则保持蹲伏，不扣跳跃体力。
- 蹲伏起跳只收跳跃费用，站起免费；成功起跳清除蹲伏意图，落地保持站立，须重新触发蹲伏才能再次蹲下。

弱跳按上升高度的 50%实现；在相同重力及同类弹道假设下，起跳速度约为正常的 `sqrt(0.5)` 倍，不能直接取 250。具体移动参数、碰撞和蓝图覆盖值由实施时核对，最终以实际轨迹验证。

## 蹲伏与输入设置

成功从站立进入蹲伏扣一次体力；维持蹲伏、蹲着行走和站起不扣。体力不足时仍以正常动作蹲下，扣完余量，并采用更长的再次进入间隔。未成功的姿态请求不扣费。

0.35/0.8 秒约束的是两次成功进入蹲伏之间的最短时间，由本次成功进入时是否扣足 10 点决定。站起不受这个计时器限制，但必须检查头顶空间，不能穿过低顶。间隔内再次请求蹲伏不排队，需要允许后重新按下，避免延迟自动蹲下和扣费。

疾跑和蹲伏分别提供按住或切换设置，默认均为按住。蹲伏按住模式松键后尝试站起，切换模式再次按键尝试站起；两种模式共用同一套扣费、空间检查和间隔规则。完整输入重映射或手柄适配不因本次设置自动纳入范围。

## 体力恢复与生命周期

- 停止消耗后等待 1.5 秒，再以 25 点/秒恢复到上限。普通移动、瞄准、射击和受伤不自动中断恢复；恢复条件满足后空中也可恢复。
- 成功执行弱跳或低体力蹲伏会重新计算恢复延迟，即使执行前体力已经为零。失败请求不扣费、不延后恢复。
- 普通行走、蹲着移动、站起和武器操作不消耗体力；体力耗尽不降低普通移动速度、瞄准稳定性或射击能力。
- 每次重生体力回满，清除旧生命的动作意图、恢复计时和相关临时状态，不继承耗尽或准备状态。
- 己方安全区正常消耗和恢复，不立即回满或额外加快恢复。基地原有保护、通行、攻击和配装规则保持有效。
- 菜单打开后停止疾跑并清除意图，世界继续运行，体力按正常时间恢复。菜单关闭不恢复旧疾跑或旧扳机意图。

## 武器衔接

开火、ADS、换弹、切枪、检视优先于疾跑。武器动作期间请求疾跑不能取消正在执行的动作；这些动作结束后需要重新触发疾跑。

开火输入立即被接受并结束疾跑，经过统一的 0.15 秒准备时间后才允许实际射击。半自动保留本次有效按下；自动武器松开扳机时取消待发。武器原有射击冷却、换弹、举枪、实例状态和三连发语义继续有效，移动准备时间不能绕过这些条件，也不能吞掉有效输入或在中断后意外补发。

切枪、死亡、菜单或生命周期结束时必须正确处理旧的待发与准备状态，不能把旧请求带入新武器或新生命。除本文明确修改的疾跑衔接外，既有枪械规则继续以枪械设计为准。

## HUD 与动作表现

2026-10-13 按用户要求简化为屏幕下方居中的白色体力条，替换原左下带数值和状态文字的体力面板。最新尺寸为 255×9（1600×900 基准），按最新反馈由 Y=700 下移至 Y=740，保持横向居中。增加淡灰色延迟层：消耗时灰色拖尾收回，恢复时白色追上灰色，方向变化延迟 0.16 秒后平滑跟随；只影响显示。体力满且没有相关受限状态时，等待显示收敛后隐藏；消耗、恢复或动作受限时显示。白色填充长度平滑跟随当前体力比例，低体力时也不变黄或变红；不显示标题、数值和状态文案，仅保留微弱暗色空槽帮助辨认耗尽状态。条与准星、拾取提示保持间距。移动限制与体力规则不变，不引入强制模糊、强烈镜头晃动或瞄准漂移。

相机、第一人称枪体与第三人称姿态各自保持明确写入职责；表现读取实际移动与体力状态，不能只用固定速度阈值猜测疾跑。逻辑中断、射击准备与视觉过渡需要相互一致，不能以视觉过渡已经存在来代替新的射击准入规则。

## 实施职责与现有代码入口

沿用 `UCharacterMovementComponent` 与现有客户端预测基础，重做本轮行为规则。速度、消耗、恢复和间隔集中配置；具体类名、文件拆分、资产形式与网络字段由实施方结合当前代码决定，不为未纳入的机动动作预建通用框架。

| 职责 | 要求 | 现有入口 |
| --- | --- | --- |
| 移动模拟 | 方向、姿态、加减速、跳跃、有效意图与移动预测；保留通用行动准入和基地边界 | `FPSMovementComponent`、`FPSDemoCharacter`、`FPSActionPolicy`、`FPSBaseMembership` |
| 输入 | 按住/切换、重新触发、菜单和生命周期清理；避免把意图等同于实际动作 | `FPSCharacterInput` |
| 体力 | 角色 GAS 表达体力及上限，统一消耗与恢复；客户端即时预测，服务器最终裁定 | `FPSDemoAttributeSet`、角色 ASC、移动模拟 |
| 武器 | 动作优先级、结束疾跑、0.15 秒射击准备、待发输入与取消 | `FPSWeaponComponent`、`FPSWeaponAbilities` |
| 表现 | 消费真实状态，协调相机、枪体、人物与 HUD | `FPSCharacterPresentation`、`FPSAvatarVisuals`、`FPSInterface`、`FPSDemoHUD` |

体力预测与移动重放必须一起设计，不能只加一个服务器定时扣费然后依赖属性复制纠正。明确权威资源、预测资源、动作序列及恢复计时的归属，防止重放重复扣费、重复请求重复跳跃、旧快照覆盖新预测或客户端时间差制造额外恢复。具体协议是实施设计，不把某个未验证实现预先声明为可靠。

2026-10-12 实施前的源码阅读定位到这些注意点：当时 `FPSMovementComponent::IsSprinting` 尚未检查实际位移与方向，`SavedMove` 仅保存冲刺意图；`FPSCharacterPresentation` 的疾跑持枪姿态使用速度大于 650 的判断，视觉上有 0.15 秒过渡，但不是本轮要求的射击准备门槛。这是历史静态阅读，不描述实施后的状态，也不作为本轮运行证据。

## 验收要求与交付边界

本节列出本轮验收条件。实施方应在独立记录中写明版本、参数、日志/截图入口和未验证项；不能覆盖既有角色三阶段记录，也不能引用旧通过结果代替新验证。

| 范围 | 必须观察的结果 |
| --- | --- |
| 基础手感 | 新速度、提速与减速、方向切换、正常跳与弱跳轨迹、蹲起和低顶空间检查；实际试玩判断手感 |
| 意图 | 按住/切换均覆盖停步保留、顶墙保留、再次前进、后退/侧移中断、武器中断、跳跃落地续跑 |
| 体力 | 6/秒消耗、仅实际地面疾跑扣费、20 点仅新启动检查、12 点停步再前进可续跑、耗尽后不自动重启 |
| 低体力动作 | 正常与弱跳扣费、零体力弱跳、两档蹲伏间隔、无自动连跳、无间隔内排队、成功零体力动作重置恢复延迟 |
| 恢复 | 正常延迟与速率、失败请求不延后、普通移动/交火/空中恢复、安全区无加成、菜单持续计时 |
| 武器 | 0.15 秒准备、半自动有效按下保留、自动松键取消、原三连发规则、换弹/切枪/举枪/射击冷却与新准备共同约束 |
| 网络 | 实际服务器与客户端分别观察；零延迟及至少 100ms 延迟/1% 丢包下验证预测、纠正与重放，不重复扣费或产生额外恢复 |
| 生命周期与模式 | 死亡、重生、菜单、回合结束清理；空手仍能移动；安全区边界、对战、靶场、AI 免体力与教学兼容 |
| 表现 | 体力条显示节奏和受限提示、动作状态与枪体/人物一致、弱跳可读；渲染与人工体验边界分别记录 |
