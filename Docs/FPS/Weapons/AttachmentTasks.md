- 状态：A1、A2 针对性验证完成；A3 改装与生命周期双端、实际拖放及迟加入专项通过，完整阶段回归待验收；补给箱模型已交付，正式改枪 UI 单独待办

依据：[配件设计决策](AttachmentDesign.md)。这里的 A1–A6 是本工作线首次交付的实施阶段，不是历史枪械重构 R1–R7 的重做。每阶段先核对当前实现，再完成实现、针对性验证与必要修复，记录证据后推进；允许在不破坏依赖的情况下调整具体实现拆分。

本清单不沿用旧枪械日志证明新功能通过。不增加随机词条、口径转换、不同弹种、实体弹匣或完整搜打撤；后续范围见 [未来想法](AttachmentFutureIdeas.md)。

2026-10-15 接续：基地改枪台已由独立 UI 工作线落地，当前说明见 [基地 UI](../UI/ExtractionUI.md)。新增后握把、枪托、枪管的实现与本轮验收由 [三部位接入记录](ModularParts.md) 集中维护；本页 A1–A6 保留首次交付范围及尚缺证据，不因新部位实现而整体勾选。

## A1：定义与统一装配解析

- [x] 核对当前定义、实例、GAS 动作接口、资源生命周期和现有资产；记录接入边界，保留无关改动与教学行为。
- [x] 增加平台、平面接口、配件定义及稳定 ID；武器与配件定义使用可保存的 PrimaryDataAsset，资源显式引用。
- [x] 分开基础定义、实例安装 ID／配置版本数据结构与解析结果；挂起装配及动作关联随 A3 行为消费接入，不提前构建嵌套接口框架。
- [x] 实现统一的兼容及属性解析，固定属性叠加规则；拒绝非法整数容量、无效倍率／时长、重复 ID、缺失定义和冲突组合。
- [x] 接入依赖集、内容一致性与加载生命周期；区分本局必需内容检查和全项目发布检查。
- [x] 为 M4 建立首批数据：瞄具、枪口、弹匣各两种参数配置；暂沿用基础表现，独立模型不计为完成；不替换现有精细 M4 样品。
- [x] 编译并验证保存／重新加载、不同装配顺序结果一致、平台兼容、无关错误与必需错误的分级处置，以及默认配置下原枪行为。

阶段出口：数据只有一份可编辑来源，新增定义可持久保存。Editor／Game 编译、数据与双端针对性证据见 [A1 实施记录](AttachmentFoundation.md)。游戏行为消费在 A3 接入；Cook／完整打包和独立配件视觉未验证。

## A2：策划表格式编辑工具

依赖 A1 的定义和解析规则。

- [x] 提供武器表、配件表、装配预览和校验结果页；支持按平台、接口及类别筛选，按需跳转资产编辑器。
- [x] 表格直接写回定义资产；提供单位、范围、说明、撤销、未保存提示和保存。
- [x] 支持模板新建／复制，生成新的稳定 ID，并清楚显示共享资源引用。
- [x] 批量修改前展示受影响资产；不建设独立可编辑的 Excel／JSON／DataTable 同步链，也不做整族品阶生成。
- [x] 实际操作新建、复制、编辑、撤销、保存和重开；核对预览与解析器结果，验证错误可定位，确认只修改预期资产。

阶段出口：策划无需修改 C++ 即可调整已支持参数、创建同类定义；实际编辑器保存重开、预览及错误定位见 [A2 实施记录](AttachmentAuthoring.md)。

## A3：手动改装、换弹事务与训练界面

依赖 A1；使用 A2 配置并检查测试数据。

- [ ] 提供最小训练改装验证入口及合法装配请求；服务器检查模式／实例／配置和当前动作，不只依赖 UI 禁用。正式改枪界面按 2026-10-13 用户要求单独后续制作。
- [ ] 接入实例装配初始化、配置版本与动作关联，分开已提交装配、待提交弹匣和客户端预览；GAS 行为消费同一解析结果。
- [ ] 打开界面停止射击、退出 ADS、取消检视，保留正在换弹；关闭后不自动续接此前按住的射击／ADS。
- [ ] 普通配件即时原子提交，保留实例 ID、冷却及后坐力恢复；装配不能以残留角色增益形式存在。
- [ ] 拖入不同弹匣触发有时长的换弹；完成时一起提交配置与弹药，取消放弃本次变更，不回滚期间的合法补给。
- [ ] 换弹中显示“换弹中”，点击该武器取消；阻止同枪第二次改装，关闭界面不取消，死亡／移除正确终止。
- [ ] 校验缩容、扩容、弹药不足与操作期间合法备弹变化，避免造弹、吞弹或旧快照覆盖。
- [ ] 将有效参数接入 GAS 共用行为路径；保持已发射子弹上下文，避免改装／切枪污染既有伤害。
- [ ] 支持已提交装配的网络复制、第一／第三人称及拾取表现，处理相关性恢复和丢弃／拾取身份保留。
- [ ] 实际服务器与客户端验证成功、拒绝、重复及过时请求、取消后重开动作、切枪／死亡／丢弃、观察者恢复与换弹退出 PIE；保留新日志。

阶段出口：装配、弹药与动作状态在服务器和客户端一致；实现与验证分别标记，未覆盖网络条件不得写为全面通过。当前实现和未通过轮次见 [A3 事务记录](AttachmentTransactions.md)，尚未满足阶段出口，条目保持未勾选。

## A4：具名本地预设与训练发枪

依赖 A3 的合法组合与实例动作边界。

- [ ] 实现本地具名预设持久化，仅保存名称、稳定武器 ID 和配件 ID；重开后使用当前定义数值。
- [ ] 校验缺失定义、非法组合及模式权限；正常游戏局内请求由服务器拒绝。
- [ ] 训练套用先校验并准备新枪，再替换同槽位、回收旧枪；新 ID、初始弹药受有效容量约束，并走正常装备就绪。
- [ ] 失败保留旧枪；退休旧动作及挂起弹匣，防止旧回调修改新枪。不自动丢旧枪，不采用“等旧换弹完成再整套应用”。
- [ ] 验证跨运行保存／加载、定义参数更新、定义缺失、失败回退、换弹中发枪和客户端越权请求；局外库存集成保持未来待办。

阶段出口：训练发枪与手动改装语义可区分，失败不丢失现有武器；记录真实双端结果。

## A5：补给站及首批美术接入

模型样品可在前述阶段期间准备；补给逻辑依赖 A3 的实例和弹药规则。

- [ ] 按 [美术规范](../Art/AssetOrganization.md) 核对现有资源和输入，制定首批配件及补给站资源清单；保留已有拾枪、治疗和选枪行为。
- [ ] 接收用户安排的制作者交付的补给箱模型；核对制作源、导出、预览和 README，并按设计文档的样品规则接入。本工作线不制作补给箱模型。
- [ ] 完成补给站及首批配件质量确认，分别记录视觉验收、转正和接入状态；未确认不自动转正式。
- [ ] 通过编辑器导入并配置模型、材质、安装位置及必要声音引用；保存重导入来源，不手改二进制资产。
- [ ] 接入服务器授权的接近交互，免费重复补两把携带武器的备弹到配置目标，超过目标不减少。
- [ ] 核对补给前后枪内弹药、实例 ID、装配不变，仍需正常换弹；不得替换成同型号新枪。
- [ ] 实际双端验证补给、重复交互、换弹期间补给、目标以上备弹及不满足交互条件时的拒绝。
- [ ] 验证瞄具／枪口／弹匣切换后的持枪与拾取外观、瞄准位置和必要音效，记录 Unreal 实机截图而非只提供 Blender 预览。

阶段出口：补给站可交互且弹药语义正确；美术制作源可追溯，样品、正式资源、实装状态清楚。

## A6：首次交付回归与维护资料

- [ ] 汇总真实服务器／客户端运行条件：构建版本、模式、人数、网络条件、操作步骤、日志与观察结果；新增动作路径必要时覆盖预测拒绝、旁观者及迟加入恢复。
- [ ] 回归原枪械开火模式、切枪中断、ADS、换弹、丢弃／拾取、玩家／人机共用路径及教学地图行为；不使用历史日志替代。
- [ ] 对新增软引用和依赖进行相称的加载、卸载、内容一致性及 Cook／打包检查；局部 Cook 和完整打包分别记录。
- [ ] 检查新增延迟操作的销毁路径，复验换弹及挂起改装期间退出 PIE；保留当前轮次证据。
- [ ] 从权威来源重新导出受影响生成资料；完善当前使用说明、实施记录及清单证据链接。
- [ ] 执行 `python Tools/CheckDocs.py` 并人工核对状态、证据、索引及美术来源；不扩大历史豁免。

阶段出口：逐项标明已完成、已验证和未验证条件，明确残留问题。文档通过、编译、局部运行和完整验收不能相互替代。
