# 枪械配件与训练改装设计决策

- 用途：设计决策
- 适用范围：FPS / Weapons，模块化配件、策划配表工具、训练改装及补给站
- 状态：2026-10-12 访谈与汇总方案已获用户确认；本文描述目标行为，不代表功能已实施
- 最后更新：2026-10-15

来源：配件设计访谈 Q1–Q32 及用户最终确认。实施进度见 [配件任务清单](AttachmentTasks.md)，暂缓内容见 [后续方向](AttachmentFutureIdeas.md)。本文是现有枪械架构上的新扩展工作线；[原重构决策](../../FPSWeaponRefactorDecisions.md) 中未纳入配件的范围描述属于原轮次，不阻止本次已确认扩展，也不撤销稳定身份、GAS、网络和资源管理规则。

## 1. 玩法目标与首次交付

最终方向是搜打撤，兼顾成长、战术取舍和自由实验。开发者扩充定义资产，玩家组合兼容配件。配件型号使用固定参数，当前不做随机词条或配件实例升级；同用途路线允许高级型号直接增强，不同用途路线保留取舍。

正式搜打撤将使用实体配件与物品资源；训练模式允许自由选择。完整背包、经济、局外仓库及搜打撤循环尚未纳入首次交付。

首次交付以 **M4、训练改枪界面、瞄具／枪口／弹匣** 为主线，每类至少提供两种可比较配置，可以包含原装配置。同时提供策划编辑工具、具名本地预设和可交互补给站。先打通参数及外观型配件，其他枪械和配件类别逐项扩展。具体数值在制作与调试时配置，不把示例平衡数值写死为需求。

不做口径转换。不同弹种、独立实体弹匣、混装顺序、嵌套接口、可切换倍率瞄具和完整搜打撤均在后续文档中维护，不借本轮自动增加穿透、弹道、延迟补偿或动态 AI 难度。

## 2. 平台、接口与装配

平台身份、安装接口和已安装配件是三个独立概念。默认使用平台专属配件；同平台武器可互换满足对应接口的配件。只有显式标为通用的配件才可跨平台，并且仍须满足接口条件。不能从模型相似、资产名称或枪械类别推断兼容。

第一阶段使用平面接口：武器声明可用接口，配件声明平台适用范围、目标接口及必要约束，装配请求检查整体组合。不同枪是否属于同一平台按定义明确配置，不预先将现有全部枪械归入同一平台。

未来确定需要转接座、导轨和部件提供子接口的关系。本轮保留稳定接口标识与扩展位置，暂不实现通用装配图框架；子接口拆卸、父子依赖和级联退回规则以后设计。

## 3. 定义、实例与有效参数

| 层次 | 保存内容与职责 |
| --- | --- |
| 武器定义 | 稳定武器 ID、平台、接口、基础参数、初始装配及显式资源引用 |
| 配件定义 | 稳定配件 ID、显示信息、兼容条件、明确的参数修正和表现资源 |
| 武器实例 | 独立 `InstanceId`、已安装配件 ID、枪内与当前简化备弹状态；运行时操作关联实例及配置版本 |
| 有效参数 | 由武器定义和已安装配件统一计算，供界面对比、行为执行和服务器裁定使用 |

有效参数不是第三份可独立编辑的配置。策划改基础定义或配件定义后重新计算，不分别手改界面数值和战斗数值。装配随枪械实例存在，不靠给角色留下一组难以清理的永久增益来表示。

### 3.1 策划数据类型

武器和配件均采用可保存的 `UPrimaryDataAsset` 作为唯一可编辑权威来源。表格式工具直接修改资产；不再维护可独立修改的 DataTable、Excel 或 JSON 参数副本。预设仅存 ID 组合，导出的检查报告仅是派生资料。

| 数据 | 类型方向 | 约束 |
| --- | --- | --- |
| 容量、连发数量 | `int32` | 有效范围、整数语义 |
| 伤害、时长、距离、倍率、FOV | `float` | 明确单位、有效范围及有限值检查 |
| 稳定定义／接口标识 | `FName` | 唯一、可校验，不以展示名称替代 |
| 显示名称与说明 | `FText` | 支持本地化 |
| 有限模式 | `UENUM` | 明确允许值 |
| 后坐力曲线 | 保存的 `UCurveVector` 资产 | 显式引用，不依赖临时内存曲线 |
| 模型、声音、曲线等资源 | 对应类型的 `TSoftObjectPtr` | 纳入依赖、校验及加载生命周期 |

编辑字段提供名称、单位、范围提示和说明；编辑器元数据不能代替保存校验、发布检查或服务器请求校验。表内可打开曲线和模型的专用编辑器，不把所有资源编辑强行塞进数值单元格。

### 3.2 参数合成规则

叠加规则按属性固定，不允许每个配件任意选择覆盖、相加、相乘而导致装配顺序改变结果。容量采用整数加值；后坐力及操作时长采用倍率修正；瞄具提供瞄准位置与固定视野参数。统一解析器按确定顺序计算并校验最终结果。

| 首批类别 | 配置内容 |
| --- | --- |
| 瞄具 | 瞄准位置、固定 FOV／视野、ADS 时长修正、模型 |
| 枪口 | 垂直及水平后坐力倍率、模型，按需要提供开火声音 |
| 弹匣 | 容量修正、换弹时长修正、模型 |

基础伤害和射速继续由武器定义供策划编辑；不是每类配件都需要修改所有属性。枪口音效替换不等于已实现消音潜行或 AI 听觉。具体字段名、解析器类名和 UI 实现方式在实施时沿用当前项目结构，不要求推倒重写。

### 3.3 2026-10-15 范围补充：M4 后握把、枪托与枪管

用户要求继续完成这三个部位，复用已落地的基地改枪台。每类提供两种固定参数型号：后握把和枪托修正 ADS 时长及纵／横后坐力；枪管还修正最大射程。倍率按稳定 ID 顺序相乘，服务器每次射击捕获有效射程；不改变基础伤害、射速或口径。参数初值可由策划工作台调整，不作为长期平衡承诺。

基地装卸沿用单人实验库存与存档事务：安装扣一件，同槽替换退回旧件，卸下恢复枪体内置部件；库存、兼容或退还空间检查失败则不提交。非弹匣配件不重新填装枪内弹药。训练模式仍复用 GAS 改装接口；基地单人仓库不因此成为联机仓库。模型、挂点及改枪台表现使用保存的显式引用，原瞄具／枪口／弹匣继续可用。实施与实际验收见 [三部位接入记录](ModularParts.md)。

## 4. 表格式策划工具

提供下列工作页，共同操作上述定义资产：

| 工作页 | 能力 |
| --- | --- |
| 武器表 | 按平台筛选，对比并编辑基础参数 |
| 配件表 | 按平台、接口及类别筛选，编辑修正参数 |
| 装配预览 | 选择组合，显示兼容原因及最终属性变化 |
| 校验结果 | 定位无效数值、资源、标识和装配冲突，跳转对应资产 |

支持撤销、未保存状态、显式保存；批量修改前展示受影响资产。支持从模板新建／复制，副本获得新的稳定 ID，资源引用可以明确共享。首次不做整族品阶配件的批量生成。保存后重新打开仍应得到相同定义及解析结果。

## 5. 手动改装、输入与动作

改装必须在背包或改枪界面中进行，第一阶段提供训练改枪界面。界面打开期间禁止射击和 ADS，服务器同样执行这一限制。

2026-10-13 用户补充：**正式改枪界面以后单独制作**。本轮只保留用于功能验证的最小训练入口，不继续扩展正式布局、美术和完整交互设计。后续界面复用已校验的装配、预览、换弹取消和预设接口；本节动作与服务器规则保持不变。独立界面工作列入 [后续方向](AttachmentFutureIdeas.md) 和任务清单，不将临时 Slate 界面视为正式 UI 交付。

| 事件 | 规则 |
| --- | --- |
| 打开界面 | 停止射击、退出 ADS、取消检视；已进行的换弹继续 |
| 修改普通配件 | 合法时即时提交，无拆装倒计时；同一把枪换弹中不接受其他装配变更 |
| 拖入不同弹匣配置 | 发起有时长的换弹，目标配置先挂起 |
| 换弹期间 | 对应武器显示“换弹中”；点击该武器取消当前换弹；可查看及对比其他方案 |
| 关闭界面 | 不取消换弹；此前按住的开火／ADS 输入不得自动恢复动作，需新输入 |
| 死亡或武器移除 | 取消未完成操作，旧操作不能继续改动实例 |

手动改装保留当前 `InstanceId`，不重置既有射击冷却或后坐力恢复进度。切枪及丢弃／拾取保留该实例的已提交装配。动作接受条件延续现有经校验的接口，不通过开放任意 setter 绕过状态所有权。

### 5.1 首阶段弹匣与弹药守恒

弹匣首先是容量配件，不是独立保存子弹的背包物品。换弹操作在提交前不改变原装配或弹药；**完成时一起提交新弹匣配置、容量和弹药，取消则放弃这次变更**。取消不回滚期间补给等其他合法操作。不接受同一把枪的第二次弹匣替换或其他改装覆盖当前待提交操作。

容量变化不能造弹或吞弹。在不涉及其他弹药来源变化的例子中：

| 原枪内／备弹 | 目标容量 | 换弹完成后的枪内／备弹 |
| --- | --- | --- |
| 20／90 | 15 | 15／95 |
| 20／90 | 45 | 45／65 |

完成时按可用总弹药与合法容量结算；缩容多余弹药归还备弹，扩容所需弹药从备弹扣除，弹药不足时不能凭空补齐。期间若发生补给等合法备弹变更，应以服务器提交时有效状态结算，不能使用过时快照覆盖新资源。旧换弹回调不得安装后续操作选中的配件。

## 6. 预设与模式边界

预设可具名并保存到本地，跨运行保留。保存名称、稳定武器 ID 和配件 ID 组合，不复制数值；以后加载读取当前定义参数。定义丢失、组合不合法时明确说明原因，保留当前武器。

正常游戏局内不能套用预设，服务器检查模式权限。允许训练模式和局外套用；局外仓库与资源扣除需要等对应系统设计，本轮不交付完整局外库存。

**训练模式套用预设是发一把新枪：**

1. 校验定义、组合、模式和必要资源，先准备可用的新实例。
2. 新实例具有新的 `InstanceId`，按定义初始弹药策略初始化，并受解析后的容量约束。
3. 成功后替换同一槽位并回收旧枪，走正常装备就绪行为；不自动把旧枪丢到地上。
4. 失败保留旧枪。退休旧实例的动作和挂起操作，旧回调不能影响新枪。

希望保留旧枪在地面时，可先执行现有主动丢枪操作。训练预设发枪与手动改装分开：不等待旧枪换弹后再整套套用，也不要求保留旧枪冷却、装配或弹药。

## 7. GAS、服务器与表现边界

武器行为仍以 GAS Ability 为核心，本地预测、服务器最终裁定，玩家与人机共用行为路径。装配管理提供经校验的请求和结果，不在每个 Ability 内各自解析一份属性。

- 服务器授权改装、取消、训练发枪和补给；客户端可预览，预览不写权威属性。
- 请求整体校验并原子提交，操作绑定武器实例及配置版本；拒绝过时回调、取消和重复请求污染新动作。
- 已发射子弹保留服务器单次射击上下文，之后切枪或改配件不能倒改该次伤害。
- 已提交装配提供足够的复制状态，支持持枪旁观者、相关性恢复及丢弃／拾取恢复；一次性表现按既有动作结果机制去重。
- 延用本局依赖集、内容一致性校验和 Asset Manager 生命周期，将所需配件及资源纳入；必需定义错误阻止相关局，无关定义错误不阻止无关局，但全项目发布校验应失败。
- 延用动作取消和退出 PIE 的销毁保护，并为新增挂起操作补充回归。UI、服务器与玩法解析统一，但不将“界面禁用按钮”视为安全边界。

实施前按当前代码核对接入点；历史重构记录说明既有基础，不能用旧日志证明新增配件已经运行通过。

## 8. 训练补给站与美术交付

制作有模型、可接近交互的训练补给站。2026-10-12 用户调整分工：弹药补给箱模型由用户安排其他制作者完成，本工作线亲自实现玩法、资源接入和验证，不再承担补给箱建模。模型未到位时先完成逻辑与可配置的资源入口，不能将临时表现当作正式美术验收。训练补给免费且可重复使用。交互将携带的两把枪备弹补到可配置目标；已经高于目标则保留，不减少。枪内弹药、实例身份及装配保持，之后仍走正常换弹。

补给不得复用“发同型号新枪”的方式偷换身份。交互按现有输入和教学行为整合，具体按键不在本次决策中固定，也不默认为可覆盖现有拾枪或治疗输入。

视觉遵循 [统一美术决策](../Art/DesignDecisions.md)：克制的工业终端、硬表面、灰黑低饱和主体和少量工业黄功能提示。保存遵循 [资产规范](../Art/AssetOrganization.md) 与 [现有整理状态](../Art/SourceOrganization.md)：

| 管理状态 | 当前位置／要求 |
| --- | --- |
| 用户交付的制作源 | `ArtSource/FPSDemo/Environment/AmmoSupplyCrate/` |
| 已导入的 Unreal 资产 | `Content/FPSDemo/Art/Environment/AmmoSupplyCrate/` |
| 玩法接入 | 使用 `Meshes/SM_AmmoSupplyCrate`；训练地图放置与补给逻辑在 A5 验证 |

用户已交付 AmmoSupplyCrate，沿用其现有位置，不迁往早期计划的 SupplyStation 目录。当前来源、预览与限制见 [弹药箱制作记录](../Art/AmmoSupplyCrate.md)；目录存在不等于补给玩法和视觉已完成验收。按需使用 `Source/`、`Textures/`、`Exports/`、`Previews/`、`Scripts/`、`Revisions/` 与资产 README。资产专用脚本随资产，跨资产工具位于 `Tools/`。

README 指明唯一当前权威来源：程序生成阶段为脚本及输入，手工精修阶段为 `.blend` 等制作工程；转换时记录入口，旧生成器不能覆盖精修结果。FBX 为派生输出。质量确认、样品转正和游戏接入分别记录，不互相替代。

配件美术遵循同样的按类别、具体资产组织规则；现有精细 M4 仍是未实装样品，不自动替换游戏模型。Industrial 混合库未迁移部分保留当前权威位置，不复制出竞争的编辑源；仅实际共享的资源进入 Shared。Unreal 二进制资产导入、移动及引用维护通过编辑器完成。
