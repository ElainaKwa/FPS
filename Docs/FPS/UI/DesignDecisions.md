# FPS UI 美术设计决策

- 用途：设计决策
- 适用范围：新 FPS 的大厅、等待房间、战斗 HUD、配装、暂停、结算及相关提示；PC 键鼠首版
- 状态：访谈规则及样稿风格已确认；用户已选定 MiSans，并确认换字体后重新对齐 UI/HUD；保留去代号与资产化要求
- 最后更新：2026-10-16

## 1. 来源、目标与边界

依据 2026-10-10 的 UI 美术访谈。目标是建立可长期扩展的统一 UI 规范，不只美化一张截图。用户选择战术与工业融合、工业行动终端气质、正式游玩界面优先，并在 Q16 明确武器采用剪影或线稿以保持轻量。

风格参考《明日方舟》《明日方舟：终末地》的规整排版、黑白灰分区、工业标识和克制强调色；FPS 布局围绕瞄准、射击和交互重新安排。不引入参考游戏的角色、Logo、队伍系统或界面功能。用户随后确认将样稿方向扩展到地图、枪械和人物的成套美术，跨系统规则见 [统一美术设计决策](../Art/DesignDecisions.md)。

“MCP”只是测试代号，玩家可见界面及场景不使用该代号或“MCP / FPS”作为品牌。正式名称未定，暂用功能标题，不补造新名称。主菜单去掉“PC · 键鼠”页脚；下列 PC 键鼠适配范围仍有效，具体操作按需保留按键提示。此调整不重命名工程、模块和文件路径。

- 先覆盖新对局，保留旧教学地图与教学 HUD。
- 首版 PC 键鼠；1920×1080 为设计基准，兼顾 2560×1440、16:10 与现有 1280×800 窗口。
- 中文负责功能、状态、错误与操作提示；少量英文和编号承担次级标识。首版不承诺双语切换。
- 最初访谈交付文档与样稿；2026-10-11 用户授权继续实现，后续要求继续细化 UI 并将 UI、建模保存为资产。当前界面见 [样稿对齐记录](SampleMatch.md)，此前基础接入见 [历史实施记录](../Art/Integration.md)。
- 帮助入口、调试显示层、布局重组等属于目标设计，不表示当前已经实现。
- UI 只呈现已有规则，不借美术调整扩展武器数值、账号保存、匹配、房间发现或模式。

## 2. 视觉语言

| 维度 | 已确认规则 |
| --- | --- |
| 基调 | 专业、清晰、轻量的工业行动终端；菜单更有视觉分区，战斗 HUD 保持清爽 |
| 表面 | 菜单与配装使用深灰背景、浅灰内容卡片；HUD 白色信息搭配局部深色半透明底 |
| 强调 | 工业黄表示选中、当前操作和重点提示；红色表示危险与错误；阵营拥有独立位置和文字/符号 |
| 字体 | 中文无衬线；通过字号和字重建立层级，重要文字不用装饰字体；时间、比分和弹药数字宽度稳定 |
| 形状 | 直角矩形为主，重要入口少量切角；细分隔线、小型标识与编号辅助组织信息 |
| 图像 | HUD 保持统一朝向的剪影；本轮配装采用现有模型的静态材质渲染图补充细节，仍使用轻量二维纹理 |
| 动效 | 短促淡入、位移；进入对局、击杀、结算可适度加强；装饰不阻碍输入 |

英文小字、细线和编号不能承担关键功能信息。黄色只强调当前重点，不把所有按钮、边框、数字同时高亮。阵营色不替代危险语义，不依赖红蓝颜色单独区分阵营。

### 首轮候选参数（待视觉评审）

以下用于出稿与后续调整，不是用户已逐项确认的颜色、字体资产或引擎参数。位图颜色以图像实际呈现为准。

| 项目 | 候选基准 |
| --- | --- |
| 背景 / 次级表面 | `#171B1E` / `#272D31` |
| 浅色卡片 / 浅底文字 | `#E4E5DF` / `#171B1E` |
| 深底主要 / 次要文字 | `#F1F2ED` / `#B8BFBE` |
| 工业黄 / 危险红 | `#E5C641` / `#E16B63` |
| 排版节奏 | 8 单位为基本间距；1080p 正文约 18–20 px，次级约 16 px，关键数字约 32–48 px |
| 页面与 HUD 安全边距 | 1080p 约 40–48 px，依视口验证；不机械同比缩小所有内容 |
| 常规动效 | 约 120–180 ms；无需等动效结束才能继续操作 |

后续“UI 也要保存为资产”的明确需求已纳入：六个主要界面使用带完整控件树的 Widget Blueprint，公共主题和纹理分别保存。2026-10-12 用户查看原版思源黑体、MiSans、HarmonyOS Sans SC 实机对比后，明确选择 **MiSans Regular/Bold**，并要求换字体后重新对齐 UI 与 HUD；英文和数字继续使用 Rajdhani。对齐以可见字形与图标、键帽、按钮的视觉中心为准，不能直接沿用旧字体的文本框坐标。字体原始文件与许可随源资源及独立包保留；准星、受伤闪烁和命中标记继续采用轻量 Canvas 绘制。编辑与生成边界见 [UI 资产说明](AssetUsage.md)。

### 2026-10-12 样稿细节对齐

用户明确指出几何框、背景细线、字体等仍不够接近样稿，要求按三张已确认样稿的具体样式实现。此要求取代首轮实装中“五把主武器全部压缩同屏”“所有按钮套用同一大切角”和右侧大幅弹匣/换弹统计的临时处理。

- 大厅：选中导航使用窄黄条、小角标及右下斜线；非选中项保持透明。预览图采用覆盖式标题和独立技术侧栏。人数加减为细框方键，底部恢复时长与矩形黄色主按钮。
- 配装：恢复三列比例、大幅浅色卡片及主武器纵向滚动，七把实际武器仍全部可选。详情恢复武器图、装备状态和两行操作反馈；打开配装时隐藏后方 HUD。
- 几何与材质：细矩形框为主，卡片仅小圆角；斜切只出现在指定角标、选中导航及少量 HUD 底板。背景细纹、稀疏辅助线和标题斜线保持低对比。
- 排版：中文明确区分常规与粗体，数字使用窄体；图形标记使用独立纹理，避免依赖缺字或回退字体。
- 等待、暂停、结算没有独立确认样稿，继承相同字体、表面和按钮组件，不据此编造额外参考页。

样稿是样式依据，实机仍使用真实状态与既有场景、枪械资产；高精度建模继续暂缓。逐项差异和验证见 [样稿对齐记录](SampleMatch.md)。

## 3. 页面与信息层级

| 页面 | 首要信息 | 结构与反馈 |
| --- | --- | --- |
| 大厅 | 单机训练、联机对局、靶场 | 终端式导航与任务卡片，局部场景预览；人数/难度/房间名/IP 在对应区域展开；不伪造不存在的匹配或房间发现 |
| 等待房间 | 阵营、本人、房主、开始条件 | 两队分栏的行动编组表，切队入口明确；满员、人数不足等在对应位置说明 |
| 战斗 HUD | 时间/比分、生命、武器/弹药 | 顶部时间与比分、左下生命、右下武器弹药；中央留给准星和短时反馈 |
| 配装 | 主副武器、当前状态、成功/失败 | 大幅居中，外围保留场景；左部选择区按主副武器分两栏，右部展示当前交互武器的剪影与状态 |
| 暂停菜单 | 继续游戏、返回大厅 | 沿用公共面板；清楚提示对局仍在运行；房主离开导致房间关闭时说明后果 |
| 结算 | 对局结果、本人成绩、前三名 | 行动报告式层级，保留返回大厅入口；只展示实际存在的排名项，不添加无数据来源的奖励或经验 |
| 帮助/调试 | 操作说明或开发状态 | 完整按键说明进入帮助；调试独立；实际影响玩家的规则通过帮助、相关位置或发生事件时提示 |

### HUD 显示节奏

- 常驻：对局时间/比分（靶场按模式显示）、生命、当前武器和弹药、必要阵营辨识、准星。
- 按状态出现：低生命、低弹药、换弹、拾取、命中/击杀、死亡/重生、安全区和配装权限反馈。
- 全局按键表、掉落清理规则和开发细节不长期占用主战斗区域；例如掉落上限实际触发时仍要告知玩家，不因简化 HUD 删除必要通知。
- 拾取提示靠近准星下方并避开目标；普通通知不能盖住瞄准中心。
- 明暗背景、低血、换弹、死亡状态均需在接入后检查，不以单张静态正常状态代替验收。

## 4. 配装的既有玩法约束

本次只调整视觉，不覆盖 [角色与配装设计决策](../Characters/DesignDecisions.md)。尤其保留：

- `P` 打开/关闭，`Esc` 关闭；打开后显示鼠标、暂停本地移动/视角/攻击输入并清除扳机意图；世界继续运行，关闭不恢复自动开火。
- 主副武器分栏，点击合法武器立即请求选择，成功后发放、装备并在本局实时保存；不新增“保存配装”“应用”或二次“领取”按钮。
- 右侧详情随悬停/焦点变化，可查看武器，但不能引入待提交的候选配装；“已装备”与“正在查看”在视觉上区分。
- 普通对局每次重生后、首次离开所属基地前可选枪；离区、死亡、阶段失效自动关闭。返回基地不会恢复本次生命的选枪权限。
- 不把“已装备”机械视作不可点击：既有规则允许合法区域内重复选同型号以补给。
- 拒绝时展示服务器原因，库存和已保存选择不变；处理中的显示不提前宣称成功。
- 靶场差异、旧枪处理、限频等按模式和既有玩法执行，不从美术图推导新的规则。

## 5. 公共组件与状态

逐步复用按钮、导航、卡片、列表、状态标签、按键提示、弹窗、HUD 数字与短通知。状态需覆盖默认、悬停/焦点、按下、选中、已装备、不可用、处理中、成功和失败；具体组件按其实际需要采用。

- 选中：强调条/背景变化加文字或符号；不只改颜色。
- 已装备：独立标识，与焦点和悬停不同。
- 不可用：可读文字说明原因，不把整个控件淡到无法辨认。
- 处理中：明确进行状态，既有服务器校验仍是事实来源。
- 失败：在相关位置提示，保留输入；错误不只有转瞬即逝的红色闪烁。
- 普通通知让位于战斗核心状态；重要告警同时提供明确文案或图形。

## 6. 尺寸与可读性

1080p 是设计基准而非唯一运行尺寸。1280×800 时优先压缩装饰、调整列宽、折叠次级信息或在列表区滚动，保留主操作、错误提示和关闭入口；不能简单整体缩成难读的小字。1440p 和 16:10 保持锚点逻辑与信息优先级。

背景适应通过局部底板、文字对比和必要描边解决，不默认依赖大面积实时模糊。降低透明度后也应能辨识卡片、按钮和焦点。所有语义颜色搭配文字或形状。武器剪影需在 HUD 实际尺寸下核对区分度，而非只检查放大图。

## 7. 样稿与后续验收边界

大厅、正常战斗 HUD 和基地配装三张样稿的整体风格已获用户认可，当前采用去代号修订版，见 [样稿记录](MockupReview.md)。该风格也是后续地图、枪械、人物的共同方向；图中的具体场景几何、数值和枪械配件仍为示意，不能视为完整资产清单、数值配置、关卡布局或运行证据。

接入时至少核对：三种目标尺寸、明暗场景、低血/低弹药/换弹/拾取/死亡、单机与联机菜单、配装成功/拒绝/自动关闭、中文长文案和键鼠操作。网络和 GAS 行为若受改动影响，必须依相关 Demo 文档进行服务器与客户端实际验证；文档检查与静态样稿均不能替代。

## 统一开始界面（2026-10-16）

用户确认启动后先选择模式，两张并列大卡片分别为“多人对战”和“回收行动”，下方提供设置与退出游戏。“回收行动”为暂定名称，之后可修改。多人对战承接原建房、加入、单机训练与靶场；回收行动进入个人工厂大厅。

界面使用“开始行动”“行动整备”“行动背包”“返回工厂”，替换原“出征／出发”“出征整备”“出征背包”“返回基地”。多人对战子页和工厂大厅均提供返回模式选择的入口；开始界面继续使用共享工业灰黑、有限黄色、MiSans 与 Rajdhani，布局和按钮保存为可编辑 Widget Blueprint。当前入口和验证见 [模式选择与回收行动入口](StartMenu.md)。

2026-10-16 用户进一步确认：开始界面不显示“本软件使用 MiSans 字体”提示，继续保留所用字体资源与许可文件。

同日用户追加确认：工厂车间采用第一人称，不显示 HUD，持有当前行动配装，工厂全区域禁止开火。工厂和回收行动在游戏视角捕获鼠标，菜单打开时光标限制在窗口内，关闭后恢复视角控制。实施与验证见 [工厂追加记录](../Maps/FactoryBase.md#第一人称与鼠标捕获修复2026-10-16)。
