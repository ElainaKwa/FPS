## 操作

| 输入 | 行为 |
| --- | --- |
| 左键 | AK/M4/冲锋枪按住连射；手枪每次按下单发；BR-3 每按一次三连发，松开完成本轮 |
| 右键（按住） | 开镜，降低 FOV 和移动速度；可与换弹并存，切枪后需松开再按 |
| R | 换弹；弹匣未满且有备弹时生效 |
| Q | 检视；开火可打断检视 |
| 1 / 2 | 立即切换主武器 / 副武器；取消当前动作，举枪准备完成前不能射击或开镜 |
| G | 丢弃当前武器，并切到另一槽 |
| F | 拾取 200 cm 内且无遮挡的最近武器；同槽已有武器则交换 |
| 左 Shift（按住） | 地面疾跑，速度为基础值的 1.5 倍；开镜、下蹲和武器动作期间不疾跑 |
| 左 Ctrl（按住） | 下蹲，速度为基础值的 0.5 倍 |
| WASD / Space | 四向移动 / 跳跃 |
| E / Esc | 治疗站交互 / 菜单；打开菜单会停止连射和疾跑、退出开镜 |

出生装备 M4 + M9；竞技场两侧放置七种武器，单人靶场在出生侧放置一组。拾取后场内展示武器不自动补充，重新进入关卡会重建。玩家丢弃的武器 180 秒后清理。死亡重生恢复出生装备，不继承已死亡角色的库存。

## 数据、GAS 与同步

- `UFPSWeaponDefinition : UPrimaryDataAsset` 保存静态配置；`UFPSWeaponCatalog` 从 Asset Registry / Asset Manager 发现、校验并加载真实资产。型号用显式稳定 `WeaponId`，槽位与类别独立配置；定义和曲线是唯一编辑来源。
- `FFPSWeaponInstance` 保存唯一 `FGuid`、稳定 `WeaponId`、弹匣/备弹、射击冷却和后坐力进度。拥有者接收完整双槽快照；其他客户端只接收当前武器与动作/ADS，地面只复制展示身份与弹药。丢弃/交换保留完整服务器实例，不重新创建满弹库存。
- `UFPSWeaponComponent` 校验服务器射速、弹药、动作冲突、拾取距离、遮挡和目标是否已被认领。客户端只能请求操作，不能提交伤害或新的弹药数。服务端串行认领防止重复拾取。
- 角色 GAS 属性增加 `WeaponDamage` 和 `MoveSpeed`，生命和持久得分沿用上一阶段。伤害通过 SetByCaller 的 GameplayEffect 应用，友伤/结算后伤害过滤继续生效。
- 共用 GameplayAbility 接管开火、弹匣换弹、切枪/举枪、检视、ADS、拾取/丢弃和取消，Ability activation 拥有 `State.Weapon.*` 标签。组件保留实例及复制职责，不再执行旧动作调度。
- 后坐力用每种武器的 `UCurveVector`：X 为俯仰角、Y 为水平角、Z 为视觉回弹，按实例的射击序号取值；开镜减小后坐力，达到恢复等待时间才重置。冷却和后坐力随枪在切换、丢弃和拾取中延续。本地预测射击与弹药，通过 GAS prediction key 和权威快照纠正；没有实现命中延迟补偿。
- `UFPSMovementComponent` 用 SavedMove 自定义压缩位同步疾跑意图，参加客户端重放；下蹲使用引擎 CharacterMovement 的同步机制。服务器与本地使用相同的 GAS 基础速度及姿态倍率。

单机大厅提供简单 / 普通 / 困难选择，默认普通。服务器开局固定 0.5 / 0.65 / 0.85 的人机对玩家伤害倍率，靶场、玩家攻击和人机互打不受影响。

## 当前表现与后续资源

第二阶段最初复用已有步枪网格，用临时缩放区分尺寸。2026-09-28 已制作并接入六种独立低多边形枪械，详见 [FPSWeaponArt.md](FPSWeaponArt.md)。开镜、检视、换弹和切枪采用程序化位移/旋转；手臂骨骼动画仍待后续制作，现有开火及操作音效已通过定义显式引用。

第三阶段 A 使用开放式机械瞄具，开镜时保留枪体；现根据各枪定义的 AimLocation 对齐镜头。

## 验证方法

`Tools/TestFPSWeapons.ps1` 启动临时双端游戏，以客户端实际 GAS Ability 输入测试连射耗尽、换弹取消、备弹不足的部分换弹、开镜、检视打断、独立槽位弹药、丢弃拾取、远距离拾取拒绝、重复拾取、GAS 伤害属性复制和疾跑/下蹲网络移动。日志为 `Saved/FPSFlowTests/Weapons-server.log`、`Weapons-client.log`。测试标记仅在显式传入 `-FPSWeaponSmoke` 的开发运行中生效。

`Tools/TestFPSFlow.ps1 -Mode LAN` 回归击倒、GAS 计分、重生与结算。以上测试不替代真人按键体验、资源视觉验收或高延迟网络测试。

以下为早期历史验证，不代表本次重构：当时通过 UE 5.8 Development Editor 编译，模块后缀 `9273`。上述真实双端武器检查与 LAN 计分回归均通过；另已用引擎离屏截图检查靶场的武器/弹药 HUD。未进行用户编辑器内的双窗口 PIE 手动按键验收，也未模拟高延迟或丢包。本次重构证据分别见第一、第二阶段实施记录。
