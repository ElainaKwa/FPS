# 第二阶段：武器系统与角色操作

> 本文记录现有实现。2026-09-28 已另行确定架构重构方案，尚未实施：参见 [设计决策](FPSWeaponRefactorDecisions.md)、[待改清单](FPSWeaponRefactorChecklist.md)和[待拓展想法](FPSWeaponFutureIdeas.md)。未来实现以其中最终决策为准，尤其是 GAS Ability、换弹开镜、切枪准备和稳定身份规则。

适用于从大厅进入的单机、局域网对局和靶场。直接打开旧教学地图仍采用教学规则。新对局使用原生 `AFPSDemoCharacter`，避免旧 `BP_FPS_Character` 保存的原始 CharacterMovement 类型覆盖新的预测移动组件；现有二进制资产没有被改写。

## 操作

| 输入 | 行为 |
| --- | --- |
| 左键 | 步枪/冲锋枪按住连射；手枪每次按下单发 |
| 右键（按住） | 开镜，降低 FOV 和移动速度 |
| R | 换弹；弹匣未满且有备弹时生效 |
| Q | 检视；开火可打断检视 |
| 1 / 2 | 主武器 / 副武器；可取消换弹，切换完成前不能射击 |
| G | 丢弃当前武器，并切到另一槽 |
| F | 拾取 200 cm 内且无遮挡的最近武器；同槽已有武器则交换 |
| 左 Shift（按住） | 地面疾跑，速度为基础值的 1.5 倍；开镜、下蹲和武器动作期间不疾跑 |
| 左 Ctrl（按住） | 下蹲，速度为基础值的 0.5 倍 |
| WASD / Space | 四向移动 / 跳跃 |
| E / Esc | 治疗站交互 / 菜单；打开菜单会停止连射和疾跑、退出开镜 |

出生装备 M4 + M9；竞技场两侧放置六种武器，单人靶场在出生侧放置一组。拾取后场内展示武器不自动补充，重新进入关卡会重建。玩家丢弃的武器 180 秒后清理。死亡重生恢复出生装备，不继承已死亡角色的库存。

## 数据、GAS 与同步

- `UFPSWeaponDefinition : UPrimaryDataAsset` 定义静态配置；当前目录由 `UFPSWeaponCatalog` 使用 C++ 创建，尚未制作独立可保存的数据资产实例。槽位、类别、型号和动作分别使用枚举，后续可以按同一结构制作数据资产。
- `FFPSWeaponInstance` 保存唯一 `FGuid`、型号和整数弹匣/备弹；`FFPSWeaponLoadout` 保存两个槽位、当前槽、动作及结束时间，作为一个结构复制。丢弃/交换保留同一编号和弹药，不重新创建满弹库存。
- `UFPSWeaponComponent` 校验服务器射速、弹药、动作冲突、拾取距离、遮挡和目标是否已被认领。客户端只能请求操作，不能提交伤害或新的弹药数。服务端串行认领防止重复拾取。
- 角色 GAS 属性增加 `WeaponDamage` 和 `MoveSpeed`，生命和持久得分沿用上一阶段。伤害通过 SetByCaller 的 GameplayEffect 应用，友伤/结算后伤害过滤继续生效。
- 换弹、切枪、检视、开镜状态映射为 `State.Weapon.*` GameplayTag；当前动作调度采用复制状态机和服务器时间，没有宣称已迁移为 GameplayAbility。
- 后坐力用每种武器的 `UCurveVector`：X 为俯仰角、Y 为水平角、Z 为视觉回弹，按连射序号取值；开镜减小后坐力。开火动画在本地立即播放，弹药以服务器状态为准；尚未实现弹药预测和延迟补偿。
- `UFPSMovementComponent` 用 SavedMove 自定义压缩位同步疾跑意图，参加客户端重放；下蹲使用引擎 CharacterMovement 的同步机制。服务器与本地使用相同的 GAS 基础速度及姿态倍率。

## 当前表现与后续资源

第二阶段最初复用已有步枪网格，用临时缩放区分尺寸。2026-09-28 已制作并接入六种独立低多边形枪械，详见 [FPSWeaponArt.md](FPSWeaponArt.md)。开镜、检视、换弹和切枪采用程序化位移/旋转；手臂骨骼动画和专用声音仍待后续制作。

第三阶段 A 使用开放式机械瞄具，开镜时保留枪体；根据各枪 SightHeight 对齐镜头。

## 验证方法

`Tools/TestFPSWeapons.ps1` 启动临时双端游戏，以客户端实际 RPC 测试连射耗尽、换弹取消、备弹不足的部分换弹、开镜、检视打断、独立槽位弹药、丢弃拾取、远距离拾取拒绝、重复拾取、GAS 伤害属性复制和疾跑/下蹲网络移动。日志为 `Saved/FPSFlowTests/Weapons-server.log`、`Weapons-client.log`。测试标记仅在显式传入 `-FPSWeaponSmoke` 的开发运行中生效。

`Tools/TestFPSFlow.ps1 -Mode LAN` 回归击倒、GAS 计分、重生与结算。以上测试不替代真人按键体验、资源视觉验收或高延迟网络测试。

本阶段已通过 UE 5.8 Development Editor 编译，模块后缀 `9273`。上述真实双端武器检查与 LAN 计分回归均通过；另已用引擎离屏截图检查靶场的武器/弹药 HUD。未进行用户编辑器内的双窗口 PIE 手动按键验收，也未模拟高延迟或丢包。
